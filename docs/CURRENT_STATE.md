# 현재 구현 상태

기준: 2026-11-17, 이 패키지의 `design/pling-app.html`.

## 실행과 구조

순수 HTML/CSS/JavaScript 한 파일, 빌드·패키지 설치 없음. 이미지와 SVG 마크는 HTML에 포함됨. API 요청이나 서버 코드 없음. 18개 화면은 `.phone[data-screen]` 요소이며 `go()`로 전환한다.

`splash`, `login`, `survey-intro`, `q1`, `q2`, `q3`, `loading`, `result`, `run`, `home`, `timetable`, `goals`, `settings`, `chat`, `calendar`, `plan-create`, `crew-create`, `crew-detail`.

초기 화면은 login이다. 별도 실행 화면은 검토용 목록으로 열 수 있다. 치즈 plan-ing 애니메이션은 취소되어 없다. 상단 화면 선택·테마·표정 도구는 디자인 검토용이다.

## 일정·타이머·보상

- 신규 일정의 제목 최대 60자, 같은 날짜의 시작<끝, 겹치는 시간은 거부. 날짜와 시간은 별도 문자열이며 자정을 넘는 일정은 지원하지 않는다. 같은 색은 여러 일정에 사용할 수 있다.
- 예시 고2 일정은 첫 사용 시 2주분(충돌이 없으면 142개)이 추가된다. `sample` 표시, 중복 방지 마커가 있다. 운영 데이터로 자동 유입시키지 않도록 후속 구현에서 분리한다.
- 오늘 진행 중이거나 다음 미완료 계획을 준비한다. 일정 상세에서 직접 선택할 수도 있다. **계획 길이 전체**를 집중 시간으로 사용하며 실제 종료 시각까지 남은 시간을 계산하는 방식은 아니다.
- 준비 상태에서 가운데 ▶ 클릭 전에는 카운트다운하지 않는다. 이후 ✓는 수동 조기 완료도 가능하다. 현재는 시간 종료 또는 ✓ 모두 계획 완료와 보상 화면을 만든다. 조기 완료 지급 정책은 후속 제품 결정 사항이다.
- 다른 화면 이동 후 재진입 시 현재 탭 메모리의 남은 시간을 이어가며, 실행 중 경과 시간은 deadline을 기준으로 계산한다. 새로고침 후 세션 복원은 없다.
- 코인 기본값 0, `plan:계획ID`별 5코인 수령. 완료 취소·재완료해도 로컬 중복 지급을 막는다. 완료 저장과 코인 지급은 서로 다른 로컬 쓰기로 서버 트랜잭션이 아니다.

## AI와 유형

채팅의 `todaySchedule`은 별도 고정 영어 단어 객체다. 메시지에서 바꾼 샘플은 실제 `events` 일정과 연동되지 않는다. `getTodayScheduleContext()`가 있으나 Gemini 호출은 없다. 해당 함수의 `todayKey`는 로드 시 계산한 값이므로 장시간 켜 둔 환경에서 날짜 갱신 처리가 필요하다.

사분면은 q2의 0/1번(시작이 어렵다/계획을 못 지킨다) 중 하나라도 선택하면 안내 쪽, 아니면 스스로 쪽이다. q3의 첫 답변이면 재정비, 두 번째면 유연 쪽. 점은 대표 위치 27/73%이며 정밀 수치가 아니다. q1(학생/직업)은 계산에 쓰지 않는다. q3 미응답이면 결과 점을 숨긴다.

유형: 차분한 설계자, 차근차근 실천가, 자유로운 탐험가, 유연한 도전가. 현재 설문 답변은 localStorage에 저장하지 않는다.

## 캐릭터 표정

최근 7일의 종료된 미완료 일정 1~2개는 울음, 3개 이상은 화남. 미완료가 없고 계획이 있는 날마다 모든 계획을 완료한 7일 연속 기록은 기쁨, 그 외는 기본. 과거 예시 일정은 사용자가 완료/취소를 직접 조작하기 전까지 계산에서 제외한다. 디자인 검토용 수동 표정 선택도 있다.

## 검증 범위

마지막 디자인 작업에서 JS 문법, 유형 4분기, 타이머 수동 시작·멈춤/재개·완료·보상 및 일부 저장 로직을 DOM 대역으로 검사했다. 실제 브라우저 시각 검증, 실제 기기·OS 알림, 서버 통합·보안·부하 검증은 완료되지 않았다. `checks/VALIDATION.md`는 이번 패키지 무결성 검증 기록이다.
