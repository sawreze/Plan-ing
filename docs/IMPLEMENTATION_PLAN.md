# 백엔드 구현 순서와 완료 기준

2026-11-18. 아키텍처 제안에 맞춰 실제 개발을 나누기 위한 작업 목록입니다. **2026-11-18 갱신: 1~3단계 서버 API 구현·통합 테스트 완료(`backend/`, 실행·결과는 `backend/README.md`).** 실제 로그인 공급자 연결, HTML 프런트 연결, 4·5단계는 미구현.

## 1단계 · 실행 기반·인증·일정

- 실제 저장소/브랜치/기존 프레임워크를 확인하고 디자인 자료와 개발 소스를 구분한다.
- 기존 서버가 없으면 제안된 TypeScript/NestJS 기반 프로젝트를 준비하고 PostgreSQL 연결·마이그레이션을 구성한다.
- 관리형 인증을 연결할 경계를 만들고 Google/Apple/이메일의 실제 공급자 설정 여부를 기록한다. 공급자 계정 설정이 없으면 로컬 검증 환경과 실연동 상태를 구분한다.
- 사용자 프로필과 타임존, 일정 CRUD·완료/취소를 구현한다. 모든 요청에서 사용자 소유권 검증.
- UTC 저장과 사용자 타임존 조회, HEX 색상·시작/끝·동시 시간 겹침을 검증한다. 색상 중복 허용.
- 계획·설정 조회 계층을 현재 HTML의 loadPlanner/persistPlanner 사용 지점과 연결하거나 연결 가능한 API 계약을 문서화한다.

완료 기준: 로컬 실행 명령, 환경 변수 예시(비밀값 제외), DB 생성·마이그레이션 명령, 인증된 일정 생성/조회/수정/삭제 테스트, 다른 사용자 접근 거부와 동시 시간 충돌 테스트. 실제 공급자 로그인 미설정 시 그 상태를 명시한다.

## 2단계 · 집중·완료·보상

- READY/RUNNING/PAUSED/COMPLETED/SKIPPED 상태와 재접속 복원.
- ▶ 클릭 전 시간 고정, 시작 후 서버 기준 남은 시간.
- 완료 기록과 보상 수령, 원장 유일 키·트랜잭션.
- 현재 UI의 수동 조기 완료도 가능한 흐름을 보존하되 보상 제한 정책은 별도 결정해 기록.

완료 기준: 진입만으로 시작하지 않음, 멈춤/재개, 종료·수동 완료, 새로고침 복원, 동일 계획의 연타/재요청/동시 수령/완료 취소 후 재완료에도 보상 1회.

## 3단계 · 목표·유형·설정

- 개인 목표 CRUD, 설문 응답과 분류 규칙 버전 저장.
- 기존 사분면의 4유형과 q3 미응답 처리 일치.
- 알림·테마 선호 저장. OS 알림 권한과 알림 선호를 별도 상태로 관리.

## 4단계 · Gemini

- 인증 사용자 타임존 기준 오늘 일정 컨텍스트와 다정한 시스템 지침.
- 변경 제안·사용자 확인·버전/충돌 재검증·확정 저장.
- 실제 events와 무관한 고정 영어 단어 샘플 연결 제거.

완료 기준: 정상 변경과 확인 취소, 날짜 변경, 버전 충돌, 모델 실패 시 일정 보존, 다른 사용자 데이터 접근 차단.

## 5단계 · 크루·알림 워커·기기 연동

- 서버 크루/멤버/초대·역할·탈퇴.
- DB 알림 예약과 워커 선점·잠금 만료·재시도·발송 결과.
- 앱 플랫폼에 맞춘 권한/기기 토큰과 APNs 등 전송 어댑터.

완료 기준: 실제 다른 사용자의 가입, 소유권/역할 검사, 일정 변경/삭제/완료/알림 끄기에 예약 갱신, 만료 토큰 처리. 실제 기기 알림과 잠금화면은 별도 기기 검증.

## 작업 기록

각 단계가 끝나면 실행·검증 방법, 완료 항목, 미연동 항목, 스키마/API 변경을 기록한다. 현재 UI의 임시 안내 삭제는 서버 기능 완성의 근거가 아니다. 배포나 GitHub 푸시는 해당 시점의 사용자 요청 범위에 맞춰 수행한다.
